# actions

Centralized reusable GitHub Actions workflows for WorkOS SDKs. Update a workflow once here and the change propagates to all downstream repos.

## Available workflows

### `block-generated-edits.yml`

Closes any PR that hand-edits an `oagen`-generated file outside its
`@oagen-ignore-start` / `@oagen-ignore-end` regions, and comments explaining
why. A file is treated as generated when its header carries an oagen marker —
`This file is auto-generated by oagen. Do not edit.`, or Go's canonical
`Code generated by oagen. DO NOT EDIT.` — and the detector keys off the marker
text, so it works for every SDK language (C#, Kotlin, TypeScript, PHP, Python,
Ruby, Go, Rust, Elixir, …). The fence markers themselves are not
hand-editable: adding, removing, or editing a fence line is treated as an
offense, since new fences only legitimately arrive via regeneration. PRs from
the SDK Automation Bot and PRs labeled `autogenerated` are exempt.

```yaml
name: Block Generated File Edits

on:
  pull_request_target:
    # No "reopened": a maintainer reopening to override the bot should not be
    # immediately re-closed. A follow-up push (synchronize) re-checks.
    types: [opened, synchronize]

jobs:
  block-generated-edits:
    uses: workos/actions/.github/workflows/block-generated-edits.yml@main
    secrets: inherit
```

### `sdk-release-readiness.yml`

Use this workflow in an organization ruleset to require scan coverage before SDK release PRs merge. Pin the workflow to a reviewed commit. Ordinary PRs pass immediately; release-please PRs wait for `Release readiness` from the WorkOS Prodsec AI App on their current revision. The workflow never checks out or executes pull-request code.

The run summary links WorkOS engineers to the internal Releases page to check progress or allow a release for its reviewed revisions. Require up-to-date branches and leave the ruleset bypass list empty so release automation follows the same rule.
